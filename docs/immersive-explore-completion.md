# 沉浸探索实现与验收记录

日期：2026-09-12。入口：[系统探索](http://127.0.0.1:4174/explore) → **全屏探索**。

本报告记录在现有 `/explore` 上增加的沉浸探索增强层。用户要求保留原来的基础结构、节点位置、颜色和视觉风格；继续以桌面端为交付范围，手机端不列入验收。以下区分源码、自动化、真实浏览器和独立审查证据。

## 范围与入口

默认 `/explore` 继续提供原有三栏布局、六核心与分层展开、系统导览、任务模拟和课程入口。场景工具栏新增“全屏探索”，以模态沉浸层提供更大的 3D 空间及深入交互。

沉浸层沿用共享的 R3F 场景、几何体、核心位置、材质与概念数据，没有另建一张互不一致的系统图。已有首页、课程、学习地图、课程解锁顺序和成绩规则不在本轮修改范围内。沿用现有 React、TypeScript、R3F、Drei、Three.js 技术栈。

进入时显示窗口内沉浸界面。顶部提供可选的浏览器原生全屏按钮；原生全屏不可用或请求失败时，显示说明并继续使用窗口内沉浸界面。退出按钮关闭增强层，恢复原页面。

## 交互能力

| 入口           | 当前实现                                                                                   | 学习目的                               |
| -------------- | ------------------------------------------------------------------------------------------ | -------------------------------------- |
| 自由探索       | 点选节点后相机聚焦；相关节点和连线保留强调；导航和详情可折叠；保留全景、模块、细节展开层级 | 先认识模块职责，再看与其他部分的联系   |
| 搜索与解释深度 | 搜索原概念及内部节点，支持键盘选取；小白显示人话与职责，标准增加定义，专业增加边界与误区   | 控制术语密度，逐步深入                 |
| 为什么这样连接 | 点击真实 3D 连线或详情中的连接条目；显示三级解释及可点选的端点                             | 理解连接传递了什么、为什么需要这条路径 |
| 关系           | 所选概念的直接上游、直接下游、全部相关；镜头容纳当前关系组                                 | 区分输入、输出与概念相关性             |
| 进入内部       | Context、Model、Harness 各有入口；只呈现本模块及内部节点；面包屑返回 AI System             | 把一个模块继续拆开看                   |
| X-Ray          | 保留六个核心，只展开当前模块；切换模块会收起上一组内部结构，当前外壳半透明                 | 在系统位置中理解模块组成               |
| 运行任务       | 复用 17 步 GPU 研究模拟，含请求、执行、结果回流、FAIL、修复、PASS 与交付                   | 观察一次任务经过系统时发生的事情       |
| 实验           | 五种单一条件改动，分别提供正常与改动后的步骤和结果；可恢复条件再运行                       | 理解缺少组件或连接会造成什么变化       |
| 图例与键盘     | 节点状态与信息、工具、回流连线说明；R 回全景，左右方向键切换步骤，Esc 退出沉浸             | 保持探索路径可发现、可退出             |

时间轴支持播放、暂停、上一/下一步、滑块拖动、单步按钮和从第一步重播。手动选择节点、连线、步骤或玩法时暂停播放，避免自动步骤覆盖用户的探索。搜索输入中的文字和方向键不触发场景快捷键；搜索候选打开时，Esc 先关闭候选。

启用 Reduced Motion 时保留手动操作，取消自动播放与长相机动画。页面转到后台时暂停，返回前台后不自动继续。WebGL 失败时保留文字入口、搜索、节点解释与时间轴操作；这条降级路径不意味着提供了等价的真实 3D 渲染。

## 内部结构与图数据

| 模块    | 内部节点                                                                                             | 结构说明                                                                                         |
| ------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Context | System Prompt、User Prompt、History、Memory Retrieval、RAG Result、Tool Schema、Tool Result，共 7 个 | 表示可能选入当前输入的组成部分，所有箭头汇入 Context；不是七道按顺序执行的工序                   |
| Model   | Token、Token Embedding、Transformer、Attention、Next Token，共 5 个                                  | Attention 在 Transformer 层内往返参与计算；下一 Token 可以追加到序列，形成有停止条件的自回归回路 |
| Harness | Agent Loop、Tool Runtime、State、Retry、Permission、Guardrail、Trace，共 7 个                        | 权限和边界控制工具执行；状态与轨迹持续更新；可恢复错误才进入受约束的重试                         |

内部节点使用 `inside-<module>-<part>` 独立 ID，位置以原模块世界坐标加局部偏移计算；原节点位置不变。每个内部节点保留正确课程映射、人话、准确定义、职责与误区。

关系模式只使用原系统图中的真实边。上游和下游仅包含直连关系；“全部相关”可保留额外相关概念及它们之间真实存在的边，不因概念相关就伪造信息流。X-Ray 的六核心背景复用现有折叠连线，保留原边 ID；“为什么”解释能说明折叠连线对应的具体子节点关系。内部视图只保留可见端点之间的连接。

## 五项实验

每项实验固定题目和其他条件，比较正常系统与单一改动后的结果。界面中的关闭或断开只影响当前教学模拟。

| 实验                       | 正常情境                                                 | 改动后的教学结果                                                   |
| -------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------ |
| 关闭 RAG                   | 从内部 GPU 评测检索相关片段，附内部引用完成比较          | 独立网页搜索仍然可用，但没有题目要求的内部证据，检查未通过         |
| 关闭 Memory                | 取回以前保存、当前对话没有重述的汇报偏好                 | 本次没有取得偏好，需要补问或恢复读取；没有删除记忆仓库             |
| 跳过 Verification          | 固定错误候选把 14 ms 写成 4 ms，检查发现错误，修正后交付 | 同一个错误候选未经核验直接交付；明确标为未核验，不生成假的 PASS    |
| 断开 Tool Result → Context | 脚本返回值和退出码进入输入，模型据实际返回报告           | 工具执行成功，但结果停在 Observation，模型无法确认真实执行结果     |
| 移除 Human Approval        | 该教学删除动作按固定策略等待人工批准                     | 只移除指定动作的审批条件；其余权限和边界仍满足时，模拟工具继续执行 |

实验不会调用真实模型、搜索服务、代码执行器或数据库。删除场景中的 `demo_db` 是虚构教学对象。实验改动后如果原图没有合法通路，不会凭空高亮一条“正常”连接，例如跳过核验时不会伪造 Model → Final 的原图边。

## 教学边界

- Model 生成回答或结构化请求；Harness 与 Tool Runtime 才执行外部动作。生成请求不等于工具已经执行。
- Context 是当前模型输入。Memory、检索结果和工具反馈只有被选入输入后才对本次调用可见；保存在外部并不等于模型当前知道。
- RAG 与独立网页搜索不能等同。关闭本例 RAG 只切断配置的内部资料路径，不宣称所有外部信息都消失。MCP 是可选协议，也不是所有工具的必经路径。
- Model 内部是常见自回归语言模型的教学抽象，不展示真实模型权重或隐藏思维。Token Embedding 与 RAG 使用的检索编码器可以不同；Attention 是 Transformer 的组成机制。
- State、Trace、Memory 职责不同。当前任务状态与过程记录不会自动变成长期记忆。
- FAIL 反馈用于继续修复，PASS 只覆盖实际定义和实施的检查范围。到达 Final 与完成核验是不同状态；移除核验实验明确保留这个差异。
- 人工批准只放行其明确范围内的动作，不会自动提供底层凭据或取消其他权限检查。等待、无回复和超时均不等于批准。

本轮未开展真实新手学习研究。技术验收和固定情境测试不能推出新手理解率、记忆效果或所有设备上的性能表现。

## 状态隔离与资源管理

沉浸控制器从原页面继承进入时的选中节点、层级、任务步骤和已保存手动视角，之后使用独立组件状态管理玩法、内部范围、搜索、解释深度、实验条件和时间轴。原页面控制器在沉浸打开期间暂停场景与任务推进。

沉浸探索不修改原页面 URL 参数，不写入全站学习 Store 或课程持久化成绩。实验重置只恢复当前模拟条件；退出后原页面继续保留进入前的位置，重新进入按原页面状态初始化。课程入口只读取解锁状态，未解锁时导向学习地图查看条件。

沉浸层使用模态对话框和 Portal，打开时锁定背景滚动，关闭时恢复。原生全屏和页面可见性监听、计时器在相应生命周期清理。场景复用按需渲染，暂停时不推进信息流；失败或关闭路径仍保留可操作的退出入口。
